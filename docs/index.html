tiny-trtllm

A ~3,700 LOC reimplementation of TensorRT-LLM's PyTorch backend that preserves 16 core architectural patterns. Learn how TRT-LLM works by reading production-quality Python.

01 Quick Start

Install

pip install torch>=2.4.0 pydantic>=2.0 transformers>=4.51.0 \
    xxhash>=3.0.0 fastapi>=0.110.0 uvicorn>=0.29.0 safetensors>=0.4.0

# Optional: TRT-LLM attention kernel (best performance)
pip install tensorrt-llm

# Dev
pip install pytest pytest-cov pytest-asyncio httpx ruff

Python API

from tinytrtllm.llm import LLM
from tinytrtllm.config import SamplingParams

llm = LLM("Qwen/Qwen3-0.6B")
outputs = llm.generate(
    ["Explain attention in one sentence."],
    SamplingParams(temperature=0.0, max_tokens=64),
)

02 Architecture Overview

tiny-trtllm mirrors TRT-LLM's real module layout. Each component maps 1:1 to its TRT-LLM counterpart.

tinytrtllm/ ├── config.py Pydantic config: TinyLlmArgs, SamplingParams ├── llm.py Top-level API: generate(), tokenize ├── engine/ │ ├── request.py LlmRequest state machine (4 states) │ ├── scheduler.py Two-tier: Capacity + MicroBatch │ ├── block_manager.py Paged KV cache + prefix cache (xxhash) │ ├── resource_manager.py prepare → update → free lifecycle │ ├── model_engine.py Forward pass + CUDA graph runner │ ├── sampler.py Async two-phase + grouped strategies │ └── executor.py PyExecutor + OverlapExecutor ├── layers/ │ ├── attention.py Plan/execute interface + registry │ ├── attention_*.py 4 backends: trtllm, fa, fi, vanilla │ ├── attention_hybrid.py Prefill/decode split dispatcher │ ├── linear.py TP-aware parallel layers │ ├── embedding.py VocabParallel + LMHead │ ├── norm.py / rotary.py RMSNorm, RoPE │ ├── activation.py SiLU*Mul │ └── moe.py Gate + TopK + fused dispatch ├── models/ │ ├── llama.py LlamaForCausalLM │ ├── qwen3.py Qwen3ForCausalLM │ └── qwen3_moe.py Qwen3MoEForCausalLM ├── distributed/tp.py NCCL TP primitives └── serve/server.py FastAPI OpenAI-compat endpoints

03 Two-Tier Scheduling

TRT-LLM's most distinctive pattern. No other inference engine separates admission control from token budgeting.

Waiting Queue │ ┌───────────▼───────────┐ │ CapacityScheduler │ Tier 1: Admission │ │ GUARANTEED_NO_EVICT: only admit if │ "Can we guarantee │ completion is guaranteed │ this request will │ MAX_UTILIZATION: admit optimistically, │ finish?" │ preempt if needed └───────────┬───────────┘ │ admitted requests ┌───────────▼───────────┐ │ MicroBatchScheduler │ Tier 2: Chunking │ │ EQUAL_PROGRESS: fair token budget │ "How many context │ across all requests │ tokens per request │ FCFS: process in arrival order │ this iteration?" │ └───────────┬───────────┘ │ ┌───────────▼───────────┐ │ ScheduledRequests │ 4 disjoint lists: │ .context_chunking │ still chunking prefill │ .context_last_chunk │ final prefill chunk → gen │ .generation │ decode: 1 token/step │ .paused │ preempted (MAX_UTIL) └───────────────────────┘

Code: Scheduling a batch

from tinytrtllm.engine.scheduler import TwoTierScheduler
from tinytrtllm.config import SchedulingPolicy, ChunkingPolicy

sched = TwoTierScheduler(
    scheduling_policy=SchedulingPolicy.GUARANTEED_NO_EVICT,
    chunking_policy=ChunkingPolicy.EQUAL_PROGRESS,
    max_batch_size=256,
    max_num_tokens=16384,
    block_size=256,
    max_blocks=1000,
)

result = sched.schedule(waiting_requests, active_gen_requests, active_blocks=0)
# result.context_chunking   → prefill requests still chunking
# result.context_last_chunk → prefill requests on their final chunk
# result.generation         → decode requests (1 token each)
# result.paused             → preempted requests

04 Plan/Execute Attention

The separation of plan() and run() is what enables CUDA graph capture. The plan computes all metadata on CPU once; the run replays on GPU.

plan(seq_lens, block_offsets, slot_mapping) │ │ Returns PreparedAttention: │ .seq_lens (batch,) │ .context_lens (batch,) │ .block_offsets (batch, max_blocks_per_seq) │ .slot_mapping (total_tokens,) │ .is_context (batch,) bool │ run(q, k, v, PreparedAttention) → output │ └─ Dispatched to backend: trtllm → thop.attention() (pip install tensorrt-llm) fa → flash_attn_varlen_func fi → flashinfer paged attention vanilla → torch.nn.functional.scaled_dot_product_attention hybrid → prefill backend + decode backend

Attention Backend Selection

# Auto-detect best available: trtllm → fa → vanilla
args = TinyLlmArgs(model_path="...", attn_backend="auto")

# Force vanilla (always works, slow)
args = TinyLlmArgs(model_path="...", attn_backend="vanilla")

# Hybrid: TRT-LLM prefill + FlashInfer decode
args = TinyLlmArgs(model_path="...", attn_backend="trtllm,fi")

05 Module Guide

engine

LlmRequest

State machine with 4 states: CONTEXT_INIT → CONTEXT_IN_PROGRESS → GENERATION_IN_PROGRESS → GENERATION_COMPLETE. Tracks chunk progress, output tokens, block table.

engine

BlockManager

Paged KV cache with deque-based free pool. Optional prefix caching via xxhash block dedup with reference counting and lazy eviction.

engine

Sampler

Async two-phase: sample_async() launches GPU kernels, update_requests() syncs CPU state. Groups requests by (top_k, top_p, temp) for batched sampling.

engine

PyExecutor

Iteration loop: fetch → schedule → prepare → forward → sample → respond. OverlapExecutor adds ping-pong: CPU processes batch N-1 while GPU runs batch N.

layer

Attention Backends

Plan/execute interface with 5 backends: TRT-LLM (thop), FlashAttention (varlen), FlashInfer (paged), Vanilla (SDPA), Hybrid (prefill/decode split).

layer

MoE Layer

Gate → softmax → TopK routing → per-expert SiLU-gated MLP → weighted combine. Single-GPU, no expert parallelism. Enables Qwen3-MoE, Mixtral.

layer

TP Linear Layers

ColumnParallelLinear (shard output), RowParallelLinear (shard input + all_reduce), QKVParallelLinear, MergedColumnParallelLinear. Weight loaders for TP slicing.

model

Model Registry

register_model() / get_model_class(). Llama, Qwen3, Qwen3-MoE registered. HF safetensors weight loading with packed module mapping.

api

FastAPI Server

OpenAI-compatible: /v1/chat/completions (streaming SSE + JSON), /v1/models, /health. Pydantic request/response models.

07 API Reference

LLM

class LLM(model_path: str, dtype="bfloat16", tensor_parallel_size=1, **kwargs)

  .generate(prompts, sampling_params=None) → list[GenerateOutput]
      prompts: str | list[str] | list[list[int]]
      Returns: list of GenerateOutput(request_id, prompt, text, token_ids)

  .is_finished → bool

SamplingParams

class SamplingParams(BaseModel):
    temperature: float = 1.0     # 0.0 = greedy
    top_k: int = 50              # 0 = disabled
    top_p: float = 1.0           # 1.0 = disabled
    max_tokens: int = 64
    ignore_eos: bool = False

TinyLlmArgs

class TinyLlmArgs(BaseModel):
    model_path: str              # HF model ID or local path
    dtype: str = "bfloat16"      # "float16", "bfloat16", "float32"
    max_batch_size: int = 256
    max_seq_len: int = 4096
    max_num_tokens: int = 16384
    block_size: int = 256
    gpu_memory_utilization: float = 0.9
    tensor_parallel_size: int = 1
    scheduling_policy: SchedulingPolicy = GUARANTEED_NO_EVICT
    chunking_policy: ChunkingPolicy = EQUAL_PROGRESS
    enable_overlap: bool = True
    enable_cuda_graph: bool = True
    enable_prefix_cache: bool = True
    attn_backend: str = "auto"   # "auto", "trtllm", "fa", "fi", "vanilla", "trtllm,fi"
